### 1.2 Split layout — one folder per party (terminal flows, sealed exchange)

Created by `node scripts\layout.ts init` (copies, never moves, from `data\lending\books` and `config\lender-policy.json`).

| Path | Party | Contents |
|---|---|---|
| `data\borrowers\<id>\books\` | borrower | its books (orion, jupiter-knitting, mercury-textiles) |
| `data\borrowers\<id>\outbox\` | borrower | `<rid>.facts.json` — the facts pack before sealing (numbers only, no names) |

| `data\lenders\harbor\policy\` | lender | `lender-policy.json` — the cut-offs (never sent to a borrower) |
| `data\lenders\harbor\keys\` | lender | `lender-harbor.key.json` (encrypted; production: AWS KMS, not built yet) |

| `data\exchange\` | crosses between them | sealed mode: only `<envelopeId>.facts.sealed.json` and `<envelopeId>.outcome.sealed.json` (ciphertext); plain mode: `<rid>.facts.json`, `<rid>.outcome.json` |

## 2. Test from the UI (the CreditSeal Desk)

### 2.1 Start it

From the repository root, one command (closes earlier Desk/console/analyst windows, starts Docker and the private chat,
runs the tests, opens the Desk):

```powershell
powershell -ExecutionPolicy Bypass -File services\lending\start-desk.ps1 -Restart -ApplicationsLog data\lenders\harbor\decisions\applications.jsonl
```

- Desk only (no Docker, no private chat): add `-NoChat`. Skip the start-up tests: `-SkipTests -SkipProof`.
- `-ApplicationsLog` turns on the lender's reapply policy for steps 4-6 and the **Applications** card. Without it the
  scripted demo repeats freely.
- Desk: `http://127.0.0.1:8750` · private-chat console: `http://127.0.0.1:8730`.

### 2.3 Isolation card (bottom of the page) — offline

Click **Run the isolation proof** (about 10 s). Expected: three rows (orion, jupiter-knitting, mercury-textiles), each
PASS in five columns — 1 facts without the rulebook · 2 no customer names / invoice ids · 3 decide without the books ·
4 no cut-offs to the borrower · **5 only sealed envelopes cross** — then the who-sees-what matrix with no red cells.
"Per-act evidence" shows the `ERR_ACCESS_DENIED` probes and act 5's refusals (third key, flipped byte, wrong sender, replay).

### 2.4 Applications card — needs `-ApplicationsLog`

1. Run step 4 (Mercury) → row #1 DECLINE.
2. Run step 4 again → row #2 **NOT CONSIDERED**, "from 2027-…".
3. Run step 6 (Orion) → row #3 APPROVE.
4. **Anchor the log on XRPL** → "✓ anchored: … entries 1-3"; each row shows "anchored ↗" (Devnet).
5. **Verify anchors (audit)** → "✓ … chain intact", "Covered by anchors: entries 1-3 of 3".

"Off" on the card means the Desk was started without `-ApplicationsLog`.

## 3. Test from the terminal

All commands from `services\lending` unless stated.

### 3.1 Everything offline in one go

```powershell
npm test                          # expected: tests 76, pass 76, fail 0, skipped 0
npm run typecheck                 # expected: no output (no errors)
node scripts\prove-split.ts       # expected: 6 x PASS, "ALL CHECKS PASSED"
node scripts\prove-isolation.ts   # expected: 3 borrowers x 5 acts PASS, "ALL ACTS PASSED"
```

`prove-isolation` options: `--exchange-mode plain` (the v1.2.0 four acts), `--books <dir>` (repeatable),
`--out <dir>` / `--keep` (keep the work folder), `--json` (what the Desk card reads), `--sandbox none` (absence only).

Facts fingerprints to expect: Orion `350c5321f348be7c…`, Jupiter `fd554d33324a04b6…` (with `--no-gleif`).
Mercury's differs between Node versions (`8223b357…` on Node 24.22, `fe4932b0…` on Node 22.23): the lender hashes the
file it receives, so this does not affect the protocol.

### 3.2 Underwrite one borrower on one machine (both halves)

```powershell
node scripts\underwrite.ts --books ..\..\data\lending\books\orion      # VERDICT APPROVE
node scripts\underwrite.ts --books ..\..\data\lending\books\mercury-textiles   # VERDICT DECLINE
```

Add `--actus-url http://34.203.247.32:8083` for the live ACTUS cross-check; Jupiter checks GLEIF live (`--no-gleif` to skip).

### 3.5 Sealed exchange (end-to-end encryption)

Set the passphrase **masked** (asterisks; never shown, never in history):

```powershell
$sec = Read-Host "Key passphrase (12+ characters)" -AsSecureString
$env:CREDITSEAL_KEY_PASSPHRASE = [Runtime.InteropServices.Marshal]::PtrToStringBSTR([Runtime.InteropServices.Marshal]::SecureStringToBSTR($sec))
Remove-Variable sec
```

Keys (once; `keys.ts init` refuses to overwrite existing keys):

```powershell
node scripts\keys.ts init --party borrower:orion
node scripts\keys.ts init --party lender:harbor
```

The exchange:

```powershell
node scripts\facts.ts --books ..\..\data\borrowers\orion\books --out ..\..\data\borrowers\orion\outbox --exchange ..\..\data\exchange --no-gleif --seal-to ..\..\data\exchange\directory\lender-harbor.pub.json --party borrower:orion --keys-dir ..\..\data\borrowers\orion\keys
$s = (Get-ChildItem ..\..\data\exchange\*.facts.sealed.json | Sort-Object LastWriteTime | Select-Object -Last 1).FullName
node scripts\decide.ts --sealed $s --sender ..\..\data\exchange\directory\borrower-orion.pub.json --party lender:harbor --keys-dir ..\..\data\lenders\harbor\keys --out ..\..\data\lenders\harbor\decisions --encryption required
node scripts\open.ts --party borrower:orion --keys-dir ..\..\data\borrowers\orion\keys --sender ..\..\data\exchange\directory\lender-harbor.pub.json --exchange ..\..\data\exchange
Get-ChildItem ..\..\data\exchange -Recurse | Select-Object Name
```

Expected: `Sealed for lender:harbor … content check passed` → `decide: opened … from borrower:orion` → `VERDICT APPROVE` →
`Delivered sealed to borrower:orion` → `Opened uw-9b8485ee7e … VERDICT APPROVE · content check passed`; the exchange
lists only `*.facts.sealed.json`, `*.outcome.sealed.json`, `directory`, and the two `.pub.json` files.
The lender's own screen shows its limit ("(limit 40 %)"); the borrower's opened outcome does not.

Refusals, by hand (run after the exchange above, in the same window):

```powershell
# 1. Replay: the same envelope a second time -> "decide: envelope … was already accepted (replay)", exit 2
node scripts\decide.ts --sealed $s --sender ..\..\data\exchange\directory\borrower-orion.pub.json --party lender:harbor --keys-dir ..\..\data\lenders\harbor\keys --out ..\..\data\lenders\harbor\decisions

# 2. One changed character in the ciphertext (a copy in TEMP) -> "the sender's signature does not verify", exit 2
$t = Get-Content $s -Raw | ConvertFrom-Json
$c = $t.ct.ToCharArray(); $c[10] = if ($c[10] -eq 'A') { 'B' } else { 'A' }; $t.ct = -join $c
$bad = Join-Path $env:TEMP "tampered.facts.sealed.json"; $t | ConvertTo-Json -Depth 10 | Set-Content $bad
node scripts\decide.ts --sealed $bad --sender ..\..\data\exchange\directory\borrower-orion.pub.json --party lender:harbor --keys-dir ..\..\data\lenders\harbor\keys --out $env:TEMP\cs-tamper

# 3. Wrong sender key (the lender's own public key instead of Orion's) -> "not from the expected sender", exit 2
node scripts\decide.ts --sealed $s --sender ..\..\data\exchange\directory\lender-harbor.pub.json --party lender:harbor --keys-dir ..\..\data\lenders\harbor\keys --out $env:TEMP\cs-wrong
```

Clear the passphrase when done: `Remove-Item Env:CREDITSEAL_KEY_PASSPHRASE`. Keep the passphrase: the key files open
only with it. In this demo one window plays both parties, so one passphrase unlocks both key files.
